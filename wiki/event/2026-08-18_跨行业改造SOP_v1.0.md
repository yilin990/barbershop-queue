# 跨行业 SaaS 模板改造 SOP v1.0

## 适用场景

QingheOS 跨行业复用：医药（pharmacy）→ 果蔬（grocery）→ 健身（fitness）→ 美容（salon）→ 餐饮（restaurant）等

## 总原则

1. **共性提取 SOP 骨架** — 6 个 Phase 标准化
2. **差异做行业检查清单** — 每行业特定词汇映射表
3. **每步都有 grep 验证**（不靠肉眼 / 不靠记忆）
4. **一次行业改造 ~1.5-2 小时**（基于 8-18 果蔬改造实战）

---

## Phase 1：环境准备（5 min）

```bash
# 1. 复制模板
cp -r ~/Desktop/qinghe-os-projects/saas-template/ ~/Desktop/qinghe-os-projects/industries/{new-industry}/

# 2. 改 package.json
#    - name: qingheos-{industry}
#    - dev port: 3010, 3011, 3012...

# 3. 改 .env.local
#    - DATABASE_URL=file:./prisma/{industry}.db
#    - JWT_SECRET={industry-specific}

# 4. 初始化
cd ~/Desktop/qinghe-os-projects/industries/{new-industry}
npm install
npx prisma db push
```

## Phase 3：AI 灵魂（30 min）⚠️ 核心

**目标文件**：
- 新建 `src/app/api/{industry}-chat/route.ts`（独立路由，不动 /api/chat）
- `src/lib/ai-tools.ts`（只取本行业相关 tools，改描述）
- `src/lib/ai-context.ts`（调整 userContext 字段）

**3 个灵魂文件**：

### 3.1 SYSTEM_PROMPT（人格 / 流程 / 边界）

```ts
const SYSTEM_PROMPT = `你是"{AI名}"，{品牌名}（{地址}）的专属{角色定位}。

⭐ 重要能力补充：
- 你不仅是{角色定位}，还连接了{品牌名}的订单系统、库存系统
- 你可以帮用户下单、查订单、查商品（工具由后端提供）
- 当你说"我帮你下个单"、"你的取货码是 XXX"，这些话都是事实

【灵魂底色】（参考 {文学/动漫角色}）
- {3 句性格描述}
- {1 句开场白范例}

【{流程名}】（必须遵守）
1. ...
2. ...
3. ...

【不许暴露内部工具】
- 你在后台可能会用 search_products / query_orders / create_order
- 不要在回复里说这些英文工具名！用 {行业语言}：
  - ❌ "我用 search_products 查到了商品"
  - ✅ "{行业人话表达}"

【必须给结果】
- 说了要查询 → 查询完成后必须告诉用户结果
- ❌ 不允许说完查询后什么都不说
- ✅ 查询完成 → 用自然语言明确告诉用户
```

### 3.2 AI_TOOLS 描述（行业语言）

| Tool | 旧描述（医药） | 新描述（果蔬）模板 |
|---|---|---|
| search_products | "感冒药"/"胃药" | "芒果"/"苹果"/"当季水果" |
| create_order | "感冒灵颗粒" | "红富士苹果 1斤" |
| query_orders | "取药码" | "取货码" |
| cancel_order | "退药" | "退款" |

### 3.3 userContext 字段调整

| 旧字段（医药） | 新字段（果蔬） |
|---|---|
| `allergy`（过敏史） | `preferences`（偏好） |
| `chronicDisease`（慢病） | `dietaryRestrictions`（忌口） |
| `medicationHistory` | `purchaseHistory` |
